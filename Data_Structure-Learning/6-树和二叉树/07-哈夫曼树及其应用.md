## 01 哈夫曼树的定义
**前置概念**：
+ **路径（path）**：树中从一个结点到另一个结点所经过的**分支构成的通路**。
+ **路径长度**：从树中一个结点到另一个结点之间的**分支数**；若规定根结点在第 1 层，则第 `i` 层结点的路径长度为 `i - 1`。
+ **结点的权**：赋予结点的**有意义的实数**，实际含义是该结点（及其子树）在整个树中所占的**比重**，例如字符出现的**频率**。
+ **结点的带权路径长度**：从根结点到该结点的**路径长度**与该结点**权值**的乘积。
+ **树的带权路径长度（WPL，Weighted Path Length）**：树中所有**叶子结点**的带权路径长度之和，即 `WPL = Σ(wi × li)`。
+ **哈夫曼树（Huffman Tree）/最优二叉树**：给定 n 个权值作为 n 个叶子结点，构造一棵二叉树，使 `WPL` 最小，这样的二叉树称为哈夫曼树。

**WPL 计算示例**：叶子权值 `W = {2, 5, 9, 6, 7}`，下图中 `2、5` 深度为 3，`9、6、7` 深度为 2：
```
            29
          /    \
        16      13
       /  \    /  \
      7    9  6    7
     / \
    2   5
```
`WPL = 2×3 + 5×3 + 9×2 + 6×2 + 7×2 = 65`。

>[!note]
>**算 WPL 的捷径**：WPL 也等于构造过程中**所有新建的非叶子结点权值之和**。上例合并产生的权值依次为 `7、13、16、29`，相加同样得 `65`——因为每个叶子的权值恰好被累加了 `li` 次（它到根的路径上有 `li` 个祖先结点）。用这个结论验算 WPL 比逐个数深度更快、更不易错。

>[!tip]
>哈夫曼树中**权值越大**的叶子结点离根越**近**，权值越小的离根越远。

## 02 哈夫曼树的构造
**贪心策略**：每次从当前森林中选取**权值最小**的两棵树，合并为一棵新树，新树的根权值为两棵子树根权值之和；重复直到只剩一棵树。

**严谨步骤**（给定各自带权的 n 个结点）：
1. 从当前的 n 个权值中选出两个**最小**的权值，让这两个结点成为**兄弟**，组成一棵新的二叉树，新树根结点的权值为左右孩子权值之和；
2. 从原权值集合中**删除**这两个最小权值，把新权值**加入**集合（集合规模由 `n` 变为 `n - 1`）；
3. 重复 1、2，直到集合中只剩下**一个**权值，它就是根结点，构造结束。

>[!tip] 形象记忆：兄弟合力找爸爸
>把这棵树**自下而上**地长出来：每次挑出剩余权值集合中**最小的两个**结点（权值相同就取这两个相同的），让它们做兄弟，两兄弟的权值相加得到**父亲**；父亲带着这个和回到集合里继续"找爸爸"，同时那两个兄弟从集合中消失。重复这个过程，直到集合里只剩下**祖宗**（根结点）。
>本质上仍是"创建一棵二叉树"，只是不能随意创建，必须按**最优二叉树的生成规则**来创建——这个规则就是**哈夫曼算法**。

+ n 个叶子结点构造的哈夫曼树共有 `2n - 1` 个结点。
+ 哈夫曼树中**没有度为 1 的结点**（每个非叶子结点都有两个孩子）。
+ 哈夫曼树**不唯一**：左右子树可以交换，权值相同时选取顺序不同也会得到不同形态。
+ 但所有哈夫曼树的 **WPL 相同**，且叶子结点的**编码长度最优**。

例如，权值为 `{7, 5, 2, 4}`，分别对应 `A、B、C、D`：
```
初始森林: (7) (5) (2) (4)
合并 2、4  -> 6:   (7) (5) (6)
合并 5、6  -> 11:  (7) (11)
合并 7、11 -> 18:  (18)
```
```
        18
       /  \
      7   11
         /  \
        5    6
            / \
           2   4
```
对应的编码为：`A = 0`，`B = 10`，`C = 110`，`D = 111`。
`WPL = 7×1 + 5×2 + 2×3 + 4×3 = 35`。

**再看一个会踩坑的例子**（`W = {2, 5, 9, 6, 7}`，即 01 节的那棵树）：
```
初始森林:   (2) (5) (6) (7) (9)
合并 2、5  -> (7):   (6) (7) (7) (9)     ← 出现两个权值为 7 的根，一个叶子一个内部结点
合并 6、7  -> (13):  (7) (9) (13)
合并 7、9  -> (16):  (13) (16)
合并 13、16 -> (29): (29)
```
第 2 步里权值 6 可以配"原来的叶子 7"，也可以配"刚合并出的内部结点 7"，两者得到的树**形态不同**，但合并权值都是 `7、13、16、29`，`WPL` 都是 `65`——这就是"形态不唯一、WPL 唯一"的直接来源。

## 03 为什么这样构造出的 WPL 最小
哈夫曼算法是**贪心算法**，其最优性由**贪心选择性质**和**最优子结构**两块拼起来，配合数学归纳法完成证明。

**引理 1（单调性，交换论证）**：设叶子 a、b 的权值为 `wa < wb`，深度为 `la < lb`（即权值小的反而浅）。把两者**互换位置**，WPL 的变化量为
```
Δ = (wa·lb + wb·la) − (wa·la + wb·lb) = (wa − wb)(lb − la) < 0
```
即把大权值往上挪、小权值往下挪能让 WPL **严格变小**。所以任何 WPL 最小的树必然满足：**权值越大深度越小**，权值最小的叶子一定出现在**最深**的位置。
（这正是"权值越大的叶子离根越近，权值越小的离根越远"这条规律的由来。）

**引理 2（最小两兄弟在最深处）**：哈夫曼树中不存在度为 1 的结点，故最深一层的叶子**成对出现**（互为兄弟）。由引理 1，最深的两个位置必须留给最小的两个权值，所以**权值最小的两个结点在最优树中必是一对最深的兄弟**。

**最优子结构**：把这两个最小叶子 `p、q` 合并为一个权值 `wp + wq` 的叶子 `c`，得到一个规模更小的子问题。反过来，子问题的任一最优树把 `c` 展开成 `p、q` 两个孩子，就有
```
WPL(原树) = WPL(子问题的树) + wp + wq
```
因此**子问题最优 ⇒ 原问题最优**（若原问题存在更优解，展开回去会让子问题更优，矛盾）。

**归纳结论**：算法每一步都合并当前最小的两个权值，把问题规模稳定地缩小 1；由引理 2 这一步没有损失最优性，由最优子结构剩余部分可递归求解，故最终得到的树 `WPL` 最小。

**关于"形态不唯一"**：同一组权值可以构造出形态不同的哈夫曼树（左右子树可交换、相同权值选取顺序可不同），但它们的 `WPL` **一定相等**。

>[!warning]
>网上常见的表述"交换任意两个叶子，WPL 都会增加"并不严谨：只有当交换使**大权值变深、小权值变浅**时 WPL 才增加；若两叶子**权值相同**，交换后 WPL **不变**。考试中判断"WPL 是否改变"时要留意这一点。

## 04 存储表示与构造算法
### 哈夫曼树的存储表示
```cpp
typedef struct {
	unsigned int weight;
	unsigned int parent, lchild, rchild;
} HTNode, *HuffmanTree;
```

### 方法一：数组存储 + Select（教材写法）
`Select` 要做的事：在 `HT[1..i-1]` 里**只看还没有双亲的结点**（即当前各棵子树的根），挑出权值最小的两个。一趟扫描即可：
```cpp
#include <climits>   // UINT_MAX

void Select(HuffmanTree HT, int n, int &s1, int &s2) {
	// 在 HT[1..n] 中选出 parent == 0（仍是某棵树的根）且权值最小的两个结点
	// 约定返回时 HT[s1].weight <= HT[s2].weight
	s1 = s2 = 0;
	unsigned int min1 = UINT_MAX, min2 = UINT_MAX;   // 最小、次小权值，初值置正无穷
	for (int i = 1; i <= n; ++i) {
		if (HT[i].parent != 0) continue;   // 已并入新树，不再是根，跳过
		if (HT[i].weight < min1) {         // 出现新的最小值，原最小值降为次小
			min2 = min1;         s2 = s1;
			min1 = HT[i].weight; s1 = i;
		} else if (HT[i].weight < min2) {  // 落在最小值与次小值之间，只更新次小
			min2 = HT[i].weight; s2 = i;
		}
	}
}

void CreateHuffmanTree(HuffmanTree &HT, int n) {
	// 构造哈夫曼树，n 为叶子结点个数
	if (n <= 1) return;
	int m = 2 * n - 1;                 // 总结点数
	HT = (HuffmanTree)malloc((m + 1) * sizeof(HTNode));  // 0 号单元不用
	if (!HT) exit(OVERFLOW);
	for (int i = 1; i <= m; ++i) {
		HT[i].parent = 0;
		HT[i].lchild = 0;
		HT[i].rchild = 0;
	}
	for (int i = 1; i <= n; ++i)
		scanf("%u", &HT[i].weight);    // 输入前 n 个叶子结点的权值
	int s1, s2;
	for (int i = n + 1; i <= m; ++i) {
		Select(HT, i - 1, s1, s2);     // 选两个权值最小的根结点
		HT[s1].parent = i;
		HT[s2].parent = i;
		HT[i].lchild = s1;
		HT[i].rchild = s2;
		HT[i].weight = HT[s1].weight + HT[s2].weight;
	}
}
```

**两趟查找版**（更好写、不易错，考场上推荐）：先扫一遍找最小，再扫一遍找"除它之外"的最小。
```cpp
void Select(HuffmanTree HT, int n, int &s1, int &s2) {
	s1 = s2 = 0;                       // 0 表示"尚未选中"
	for (int i = 1; i <= n; ++i) {     // 第一趟：权值最小的根
		if (HT[i].parent == 0 && (s1 == 0 || HT[i].weight < HT[s1].weight))
			s1 = i;
	}
	for (int i = 1; i <= n; ++i) {     // 第二趟：跳过 s1，再找最小
		if (HT[i].parent == 0 && i != s1 && (s2 == 0 || HT[i].weight < HT[s2].weight))
			s2 = i;
	}
	if (HT[s1].weight > HT[s2].weight) {   // 统一约定 s1 的权值不超过 s2
		int t = s1; s1 = s2; s2 = t;
	}
}
```

>[!warning] `Select` 的四个易错点
> + **必须过滤 `parent != 0`**：只有还没有双亲的结点才是当前森林的根；漏掉这个判断会把已经合并过的内部结点重新选出来，树就错了。
> + **`s1、s2` 要用引用（或指针）返回**，形参写成 `int s1` 的话结果带不回调用处。
> + **权值相等时选哪一个都行**：用严格 `<` 比较会保留先出现的结点，两种选择只影响哈夫曼树的**形态**，不影响 `WPL`。若题目要求画出唯一确定的树，一般再补一条约定——权值相同时取**编号小的作左孩子**。
> + 一趟版里更新最小值时必须**同时把原最小值降级为次小值**（`min2 = min1; s2 = s1;`），只改 `s1` 会让 `s2` 停留在旧的最小值上，两个下标可能相同。

`Select` 每次扫描 `O(n)`，共合并 `n - 1` 次，所以方法一的构造总时间是 `O(n²)`——这正是方法二要用堆的地方。

### 方法二：优先队列（最小堆）
构造过程的核心操作是"**每次取出最小的两个**"，这正是**优先队列（PriorityQueue / 最小堆）**的拿手活：先把 n 个单结点全部入队，每次出队两个最小的合并，再让"父亲"带着合并后的权值回队，直到队列里只剩根结点。

```cpp
struct Node {
	unsigned int weight;
	Node *lchild, *rchild;
};

struct Cmp {                       // 自定义比较器：反着写才是小顶堆
	bool operator()(const Node* a, const Node* b) const {
		return a->weight > b->weight;
	}
};

Node* CreateHuffmanTreeByPQ(const std::vector<int>& weights) {
	std::priority_queue<Node*, std::vector<Node*>, Cmp> pq;
	for (int w : weights)
		pq.push(new Node{static_cast<unsigned int>(w), nullptr, nullptr});
	while (pq.size() > 1) {
		Node* l = pq.top(); pq.pop();   // 权值最小
		Node* r = pq.top(); pq.pop();   // 权值次小
		// 兄弟合力找爸爸，爸爸带着权值之和回到集合里
		pq.push(new Node{l->weight + r->weight, l, r});
	}
	return pq.top();                    // 队列中最后一个结点即根
}
```

Java 写法（`PriorityQueue` 默认按 `compareTo` 构成小顶堆）：
```java
class HuffmanNode implements Comparable<HuffmanNode> {
	int weight;                 // 权值
	HuffmanNode left, right;    // 左右孩子

	HuffmanNode(int weight) { this.weight = weight; }

	@Override
	public int compareTo(HuffmanNode other) {
		return this.weight - other.weight;   // 权值小者优先
	}
}

public class HuffmanTree {
	public static HuffmanNode buildHuffmanTree(int[] weights) {
		PriorityQueue<HuffmanNode> pq = new PriorityQueue<>();
		for (int weight : weights) pq.add(new HuffmanNode(weight));
		while (pq.size() > 1) {
			HuffmanNode left = pq.poll();    // 弹出权值最小的节点
			HuffmanNode right = pq.poll();   // 弹出权值次小的节点
			HuffmanNode parent = new HuffmanNode(left.weight + right.weight);
			parent.left = left;
			parent.right = right;
			pq.add(parent);                  // 新节点回队
		}
		return pq.poll();
	}

	// 自顶向下传前缀：左分支记 0、右分支记 1，走到叶子就得到该结点的编码
	public static void printHuffmanTree(HuffmanNode root, String prefix) {
		if (root == null) return;
		if (root.left == null && root.right == null)
			System.out.println(root.weight + " -> " + prefix);
		printHuffmanTree(root.left, prefix + "0");
		printHuffmanTree(root.right, prefix + "1");
	}

	public static void main(String[] args) {
		printHuffmanTree(buildHuffmanTree(new int[]{2, 5, 9, 6, 7}), "");
	}
}
```

**两种实现对比**：

| 实现方式 | 单次"选最小两个" | 构造总时间 | 求哈夫曼编码的方式 |
| --- | --- | --- | --- |
| 数组 + `Select`（方法一） | `O(n)` | `O(n²)` | 结点带 `parent` 域，从**叶子向根回溯**、逆序记 0/1 |
| 优先队列 / 最小堆（方法二） | `O(log n)` | `O(n log n)` | 没有 `parent` 指针，需从**根向叶子**递归传前缀（或额外记录 `parent`） |

>[!warning]
> + 方法一的瓶颈全在 `Select`（线性扫描找最小两个），n 很大时用方法二；两种写法都接受，但要写清复杂度。
> + `compareTo` 用 `this.weight - other.weight` 做减法，权值极大时可能**整型溢出**，工程上应改用 `Integer.compare(a.weight, b.weight)`。
> + 需要输出**编码表**时优先用方法一（有 `parent`，能直接回溯）；方法二的树只有孩子指针，得自顶向下走。

## 05 哈夫曼编码
**前缀编码**：任一字符的编码都不是另一个字符编码的**前缀**，因此解码时不会产生歧义。
+ 以字符出现的**频率（或次数）**作为权值构造哈夫曼树。
+ 从根到叶子的路径上，**左分支记 0，右分支记 1**，得到每个字符的哈夫曼编码。
+ 哈夫曼编码是**不等长编码**，频率高的字符编码短，频率低的字符编码长，从而使总编码长度最短。
+ 哈夫曼编码是**前缀编码**，且是**最优前缀编码**。

**编码示例**：对 01 节那棵 `W = {2, 5, 9, 6, 7}` 的哈夫曼树，左支记 0、右支记 1，从根走到各叶子：

| 叶子权值 | 深度 | 编码 |
| --- | --- | --- |
| 2 | 3 | `000` |
| 5 | 3 | `001` |
| 9 | 2 | `01` |
| 6 | 2 | `10` |
| 7 | 2 | `11` |

总编码长度 `= 2×3 + 5×3 + 9×2 + 6×2 + 7×2 = 65 = WPL`，与树形态无关。

>[!note]
>代码跑出来的编码常与上表**左右相反**：上面 `Select` 约定把权值小的（`s1`）当左孩子，程序可能给出 `2→100、5→101、9→11、6→00、7→01`。形态是同一棵树的镜像/等价变体，**码长分布仍是 3、3、2、2、2**，所以 `WPL` 和总编码长度都不变——这正好印证上面的"编码不唯一"。

**编码算法**：从叶子结点出发，沿双亲指针向上回溯到根，**逆序**记录分支的 0/1。
```cpp
typedef char **HuffmanCode;

void HuffmanCoding(HuffmanTree HT, HuffmanCode &HC, int n) {
	// 从叶子到根逆向求每个字符的哈夫曼编码
	HC = (HuffmanCode)malloc((n + 1) * sizeof(char *));
	if (!HC) exit(OVERFLOW);
	char *cd = (char *)malloc(n * sizeof(char));  // 临时存放编码
	cd[n - 1] = '\0';
	for (int i = 1; i <= n; ++i) {
		int start = n - 1;             // 编码结束符位置
		int c = i;
		int f = HT[i].parent;
		while (f != 0) {               // 从叶子回溯到根
			--start;
			if (HT[f].lchild == c) cd[start] = '0';  // 左分支
			else cd[start] = '1';                    // 右分支
			c = f;
			f = HT[f].parent;
		}
		HC[i] = (char *)malloc((n - start) * sizeof(char));
		strcpy(HC[i], &cd[start]);     // 复制编码
	}
	free(cd);
}
```

**译码**：从根出发，按编码串的 0/1 走左/右分支，走到叶子结点输出对应字符，再回到根继续。

>[!tip]
>哈夫曼编码的总长度就是哈夫曼树的 **WPL**；若字符 i 的频率为 `wi`，编码长度为 `li`，则总编码长度 = `Σ(wi × li)`。

>[!warning]
>哈夫曼编码**不唯一**：左、右分支的 0/1 约定可以互换，权值相同的字符编码长度相同但具体编码可能不同；但**平均码长**和**总编码长度**相同。

## 06 哈夫曼树的应用
+ **数据压缩**：根据字符频率构造哈夫曼编码，频率高的字符用短码，从而减少总存储空间。
+ **文件编码/译码**：发送方按哈夫曼编码表编码，接收方按同一棵哈夫曼树译码。
+ **最佳判定树**：将多个判断条件按概率构造哈夫曼树，使平均判断次数最少。
